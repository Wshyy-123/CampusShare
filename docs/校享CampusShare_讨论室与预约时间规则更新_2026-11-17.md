# 讨论室与预约时间规则更新

后续范围更新：PO同日决定所有场地仅支持当天预约；本文件中较早的未来预约说明按历史理解，以[仅当天预约调整](校享CampusShare_仅当天预约调整_2026-11-17.md)为准。

日期：2026-11-17。PO明确更新规则，本轮已在本机主工程实现并验证，尚未提交或推送GitHub。

## 当前规则

1. 讨论室按整间预约，允许预约当天或未来尚未开始的开放时段，取消原“必须提前一天”要求。开放、停用、外部/教学占用及预约冲突校验继续执行。
2. 讨论室本人预约为`RESERVED`且服务端时间严格早于开始时间时，可主动取消。取消立即释放本次占用，保留`USER_CANCEL`及事件历史，重复操作幂等；不解除其他占用或恢复停用资源。开始时刻起、已使用、已完成等状态不可主动取消。
3. 管理员取消自己的讨论室预约遵循同样规则；本次不新增取消他人预约的权限。讨论室不自动套用座位刷卡和30分钟、教室/体育扫码与15分钟规则。
4. 所有资源的新预约开始时间不得早于服务端当前时间，结束时间必须晚于开始时间。例如现在10:00，09:00—11:00不能提交，不能仅凭结束时间还没到而放行。所有带时区的输入统一转换为`Asia/Shanghai`后判断。
5. 同一`clientRequestId`的重试仅找回已有预约，不会新建第二条记录；原请求成功后时间已过，也不应错误地报告重试为新预约成功。

本文件及《项目背景与业务规则》V1.5覆盖旧文档、原XIA-12故事中“提前一天”的历史条款。原故事导入材料保留作为历史记录；本轮没有修改PingCode。

## 实现与扩展入口

- 后端仍在`campus-share-backend/`：`ReservationService`移除讨论室前一自然日限制，保留取得资源锁后的服务端时间检查；`ResourceService`为讨论室返回当天剩余可用区间；共享取消入口`POST /api/v1/reservations/{id}/cancel`允许讨论室，沿用Session、CSRF、本人归属校验、共同锁、事务及历史写入。
- 前端仍在`frontend/`：发现页不再把讨论室日期强制改为明天；详情页提供讨论室取消，且不显示不适用的地点扫码操作。`useCurrentTime`每秒更新打开页面的时间条件；快捷时段和提交按钮在开始时间过去后禁用，适配器与演示服务提交前再次检查。自选表单默认今天，列出尚可预约区间，时间输入按分钟选择，避免动态最小时间与半小时间隔发生原生校验冲突。
- 统一文案及API以当前业务规则、`docs/api/reservations.yaml`、`docs/api/sports-attendance.yaml`为准。无新增SQL迁移，已有001至007不重放；不删除或重置既有预约。
- 本机需重新构建并重启后端；仅刷新前端不能替换Java服务。本轮已启动新版后端，原会话失效后重新登录即可。
