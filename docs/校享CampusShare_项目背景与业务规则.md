# 校享 CampusShare 项目背景与业务规则

版本：V1.3｜更新日期：2026-11-13｜适用对象：全体产品、开发与测试成员。

本文件统一产品背景、业务流程和验收要求。前后端约定引用本文件的规则，已有PingCode工作项按本次变化同步。文档描述开发目标，不表示代码、联调或验收已经完成。

## 一、项目目标

校享 CampusShare——校园公共场地预约与管理平台，将图书馆、教室、体育场所的查询、预约、到离场及自动释放集中管理，减少冲突和资源空占。

- 学生、教师查询并预约，资源管理员维护资源、开放、占用和停用安排；首版预约不审批。
- 浏览器访问，兼顾电脑和手机；Vue 3 + TypeScript + Vite，Java 21 + Spring Boot，MySQL 8.4 LTS。
- 图书馆座位和刷卡事件采用模拟数据与入口；教务占用和体育外部占用采用模拟数据，不接入真实学校教务或校园卡系统。
- 教室和体育扫码用真实手机验证，成功以服务端登记为准。
- 团队8人：1名PO、1名Scrum Master、6名开发；当前PO为宋柳克。团队职责与业务角色分别管理。

## 二、资源与占用

| 类型 | 最小预约单位 | 可用性来源 |
|---|---|---|
| 图书馆座位 | 一个座位 | 模拟座位、开放/停用、系统预约 |
| 教室 | 一整间教室 | 模拟教务教学占用、开放/停用、系统预约 |
| 乒乓球、羽毛球、网球 | 一张球桌或一块场地 | 模拟外部占用、开放/停用、系统预约 |
| 图书馆讨论室 | 一整间讨论室 | 开放/停用、系统预约；沿用提前一天预约 |

北体育馆乒乓球桌的教学时段作为不可约占用；教室教学时段不可约。模拟占用是明确的时段数据，不在每次查询时随机改变。

可约条件同时满足：在开放时段、未停用、没有重叠教学/外部占用、没有重叠有效预约。同一排他资源的重叠时段最多一个有效预约，提交时由后端重新检查。

释放只解除对应预约占用，保留历史，不清除模拟课表、外部占用、他人预约或仍生效的停用。

## 三、三类核心流程

| 类型 | 入场确认 | 未到处理 | 正常结束与释放 |
|---|---|---|---|
| 图书馆座位 | 模拟刷卡入场，关联本人预约 | 预约成功起30分钟未到，取消、释放并记录违规 | 模拟刷卡离场，立即完成本次预约并释放 |
| 教室 | 预约账户扫描对应教室码 | 预约开始起15分钟未签到，取消并释放 | 到预约结束时间自动完成并释放 |
| 体育场所 | 预约账户扫描对应球桌/场地码 | 预约开始起15分钟未签到，取消、释放并记录违规 | 到预约结束时间自动完成并释放 |

### 图书馆座位

- 30分钟从服务端确认预约成功的accepted_at计算，不从使用开始时间计算。
- 不允许主动取消；已入场后刷卡离场是结束使用，不能与主动取消混为一谈。
- 入场和离场事件明确区分；重复入场不切换为离场，重复离场不重复释放。
- 已超时或取消的预约不能被迟到刷卡恢复，离场保存时间与使用历史。

### 教室与体育

- 同时实现未签到超时释放和正常结束释放，两者的计时基准、状态与原因分开。
- 已成功签到不再按未到处理；正常结束记COMPLETED，不记未到违规。
- 教室未到实现取消和释放，本次不增加其违规处罚。体育未到保留原违规记录。
- 体育使用前可按规则取消；原扫码签退记录保留，正常结束释放不以签退为前提。本次不新增提前体育签退立即释放规则。
- 自动任务由后端执行，关闭页面或管理员未操作仍然成立，恢复后补查积压。

### 讨论室

按整间房预约，最晚在使用日期前一自然日提交，不要求满24小时，当天不能预约当天。不将座位或教室到离场规则自动套用于讨论室。

## 四、地点二维码和直接签到

1. 每个教室、每张球桌或每块场地绑定稳定资源标识并生成对应地点码，展示资源名称与位置，不能只识别整座体育馆。
2. 扫码识别地点后可自动发起签到；未登录先登录，再返回原地点处理，不需管理员人工逐条确认。
3. 后端核对已认证账户、本人预约、资源、允许签到时间、状态及停用情况，成功后保存签到事件；不信任前端传入的userId。
4. GET只查询地点；POST按Session/CSRF流程写签到，网页预览不能触发签到。
5. 他人账户、错误地点、不满足时间条件或失效预约均不能签到；重复扫码返回已有结果，不重复记账、不自动签退。
6. 签到凭据记录预约、账户、资源、服务端时间及扫码来源。静态码可作为课程业务登记依据，不能独立证明人确实在现场；定位和动态码不在本次新增范围。

例：本人预约羽毛球2号场地18:00—19:00，在允许窗口扫描2号场地码登记成功；扫描1号场地或其他账户扫描不能签到该预约。未到达到15分钟期限则取消；已签到预约19:00自动完成。

## 五、状态与一致性

| 状态 | 含义 |
|---|---|
| RESERVED | 已预约，未确认到馆 |
| CHECKED_IN | 已确认到馆 |
| COMPLETED | 正常结束，不再占用，保留历史 |
| CANCELLED | 主动取消、未到或停用导致失效，不再占用，保存原因 |

签到、离场和后台任务采用共同服务端时间、事务及锁顺序：先锁资源，再锁预约，重读后判断；状态和相关历史、违规一致提交，失败回滚。重复请求、扫描和并发任务不重复释放或记违规，不影响后来预约。

后台分别处理座位30分钟、教室/体育15分钟、教室/体育预约结束。不能扫描全部RESERVED后统一作为体育未到。

## 六、验收要求

以下是应执行的验收场景，不是已有结果：

1. 教务/体育模拟占用与系统预约共同决定可约，查询与提交校验一致。
2. 两人并发预约同一资源重叠时段最多一人成功。
3. 本人扫描正确地点且满足时间可签到；他人、错误地点、时间不符或失效预约被拒绝。
4. 未登录扫码后登录保留地点；重复扫码不重复签到、不切换为签退。
5. 座位按成功起30分钟，教室/体育按开始起15分钟处理未到，页面关闭仍有效。
6. 已签到教室/体育到结束自动完成，不能被未到任务误取消或处罚。
7. 图书馆刷卡离场立即完成释放；重复事件不影响新预约，历史保留。
8. 并发、失败回滚及停机恢复保持一致，不留半完成状态。
9. 释放预约不解除仍生效的课表、外部占用或停用。
10. 真实手机、前后端与数据库联调后判定故事完成，模拟页面或单模块CI不能代替全流程验收。

## 八、管理接口的一致性约束（2026-11-13）

开放与教学时段操作通过type和scheduleId共同定位，修改/删除保留前后快照。新增教学占用不能与有效预约冲突；调整开放时间不能使有效预约失去开放覆盖，冲突时整次拒绝并保留原状态。需要取消受影响预约时使用停用流程，保留原因和历史。

整资源停用与时段停用复用同一取消/进行中保护逻辑，重新启用不恢复已取消预约、不清除教学或停用区间。有预约历史的资源不能变更类型。上述为保持既有预约规则的接口约束，不新增审批、处罚或未到期限。

当前接入范围、数据库升级与成员执行说明见[管理与生命周期集成说明](校享CampusShare_管理与生命周期集成说明_2026-11-13.md)。产品目标与实际交付仍分别判断。
