## 1. 目的

验证 XIA-5/XIA-6 在当前预约垂直切片中的功能、边界、异常、权限、并发和幂等行为，确认：

1. 合法预约能生成归属于当前登录用户的有效记录，并可查询；
2. 重叠、停用、教学占用、非开放时段不会被接受；
3. 并发和重复提交不会产生第二个有效占用或重复记录；
4. 我的预约只返回本人记录，他人记录不泄露；
5. 前后端契约、数据库状态和页面展示一致。

## 5. 测试策略

### 5.1 分层

| 层级 | 方法 | 工具/入口 | 主要覆盖 |
|---|---|---|---|
| 单元/组件 | 参数、期限、时间转换、状态判断 | JUnit 5 / Spring Boot Test | 座位 30 分钟、体育 15 分钟、UTC→上海、开始=结束 |
| 集成 | MockMvc + 真实数据库方言 | H2 MySQL 模式、MySQL 8.0.12 | 创建、冲突、阻塞、停用、幂等、列表、详情、权限 |
| 并发 | 多线程同时调用 Service，真实行锁 | MySQL 8.0.12；H2 跳过并发 | 重叠冲突、同一 clientRequestId 并发 |
| 接口端到端 | 真实会话 + CSRF，经 Vite 代理 | Python requests + 运行中的前后端 | 登录→资源→创建→查询→越权 |
| 前端静态检查 | 类型检查 + 生产构建 | `vue-tsc -b && vite build` | 类型、组件、路由、打包 |
| 前端 GUI | 真实浏览器点击/观察 | ZCode IAB | 登录、表单、成功/失败反馈、列表、详情、窄屏 |
| CI | MySQL 8.4 service + 构建 | GitHub Actions | 团队基线数据库上的全量测试和前端构建 |

### 5.2 并发与幂等

- 同一资源写入统一先锁 `resource` 行，再锁定读开放安排和有效预约。
- 拿到资源锁后，`clientRequestId` 的重查必须使用 `FOR UPDATE` 锁定读；不能依赖等待锁之前建立的 REPEATABLE READ 快照。
- 数据库 `(user_id, client_request_id)` 唯一约束作为重复提交的最终兜底。
- 同参重放返回原预约；异参返回 `IDEMPOTENCY_CONFLICT`。
- 并发重叠由 `RESERVATION_CONFLICT` 拒绝，数据库只保留一个 `RESERVED/CHECKED_IN` 占用。

### 5.3 安全与权限

- 创建预约不接收 `userId`，身份来自服务端 Session。
- 写请求必须携带 `/api/v1/auth/csrf` 返回的 CSRF 请求头；缺失/错误返回 `CSRF_INVALID`。
- 我的预约只按当前用户查询；他人预约详情统一 404，不泄露存在性。
- 错误响应带 `requestId`，不返回密码摘要、Session 或堆栈。

### 5.4 前端

- 请求统一走 `src/api/http.ts`，自动获取/携带 CSRF，401 统一回登录。
- 表单提交中禁用按钮只是体验优化，最终结果以接口为准。
- 预约提交失败保留同一 `clientRequestId` 供网络重试；参数变化才生成新值。
- 列表/详情覆盖加载、空、失败、状态文字和取消原因。
- 手机窄屏检查表单可点、卡片不溢出、按钮可触达。

### 5.5 测试数据

- 每次自动化测试前重建测试夹具，清空预约/事件/阻塞/开放，重新插入开放安排。
- 真实联调使用 `002_demo_data.sql` 的虚构账号、资源、开放安排、教学占用和演示预约。
- 不把真实人员、真实密码或生产数据写入测试库。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 本机 8080 被占用 | 后端无法按文档端口启动 | 默认 8081，Vite 代理同步；README 说明可用 `CAMPUSSHARE_PORT` 覆盖 |

| 时间相关测试接近午夜/时区问题 | 日期漂移导致误判 | 使用 D+1、服务端 Clock、Asia/Shanghai；测试数据动态生成 |
| 演示数据脚本重复执行 | 唯一键冲突或重复预约 | 文档说明空库执行一次；测试夹具单独重建 |
