## 覆盖的实际场景

| 场景 | 结果 |
|---|---|
| 停用与预约重叠 | 只取消有效且受影响预约，保留取消原因与操作者、历史 |
| 不重叠、其他资源、已完成和已取消记录 | 原样保留，不删除 |
| 停用区间结束与预约开始相等 | 不算重叠 |
| 已开始使用的预约位于范围内 | 409，整次请求不写停用或取消 |
| 提前签到且尚未开始使用 | 可以取消；输入UTC偏移转换为上海时间 |
| 停用后取消占用 | 共享可用性检查继续拒绝停用时段 |
| 原事务已有旧RR快照 | 锁定读仍读取到刚提交的停用安排并拒绝预约 |
| 停用写历史失败 | 停用安排、取消状态一起回滚 |
| 未登录、普通用户伪造管理员authority | 服务端拒绝 |
| 座位10:00确认成功，10:29:59.999 | 不释放 |
| 座位10:00确认成功，10:30:00 | 释放并记录一次NO_SHOW违规和取消事件 |
| 期限内有效确认到馆 | 不取消、不记未到违规 |
| 体育资源 | 不被座位任务处理 |
| 已取消和重复扫描 | 不再取消或重复记违规，不影响后来预约 |
| 停机积压到期预约 | 后续扫描仍能处理 |
| 释放后模拟创建新预约 | 旧记录保留，新预约可建立有效占用 |
| 写违规失败 | 预约取消和历史一起回滚 |
| 两个超时处理线程 | 一个成功，一个无操作，只有一份违规和事件 |
| 有效到馆持有资源锁时遇到超时处理 | 超时方重读最新状态，不取消有效到馆预约 |
| 停用与超时处理并发 | 一次取消、一次历史；只有超时方先成功时记违规 |
| 后台调度启动且无HTTP请求 | 自动触发扫描 |
| 单个候选异常 | 继续处理后续候选，下轮可重试失败记录 |
| 停用HTTP接口 | 验证时间和参数，成功返回字符串ID和追踪号 |
