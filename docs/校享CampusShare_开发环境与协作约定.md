## 一、环境

| 类别 | 方案 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite，Node.js 24，npm，VS Code |
| 后端 | Java 21，Spring Boot 3.5.16，MyBatis Starter 3.0.5，IDEA，Maven 3.9.x + Wrapper |
| 数据库 | MySQL 8.4 LTS，InnoDB，utf8mb4；开发各自本地库，后续共同联调 |
| 代码与需求 | GitHub同一仓库、功能分支和PR；PingCode工作项 |
| 检查 | GitHub Actions，类型检查、构建和相关测试 |

提交依赖锁文件和Wrapper配置，补丁版本写入启动说明。phpStudy用于管理本地MySQL，不改变数据库版本基线。连接信息通过本地配置或环境变量填写，不提交真实密码。

## 二、工程与接口

- 当前前端frontend/，主后端campus-share-backend/；文档docs/。独立库接入共享主工程，不分建三套生产系统。
- 业务按类型应用规则，共用状态、认证、事务和可用性检查；原模块接入时统一依赖、扫描和共享表结构。
- 接口/api/v1，JSON字段camelCase、ID字符串、code/message/data/requestId；具体请求和错误例子在docs/api/维护。
- 业务时区Asia/Shanghai，后端时间为准；数据库snake_case，前端/Java方法camelCase；UTF-8，统一LF，格式以项目配置执行。
- 数据库用顺序编号SQL脚本，已应用脚本不静默重写；成员同步代码时同步迁移版本，不能只改个人库。
- 前端参考Vue Bits，使用共用主题和控件；AI生成与手写代码执行相同检查，提交者能解释实现。

## 三、演示与完成标准

- 模拟座位与刷卡入场/离场；模拟教务/体育占用与系统预约合并；不声称已接真实校园系统。
- 手机扫码识别具体地点，后端核对当前账户与本人预约后登记；扫码未登录则登录返回，不能靠固定用户ID演示真实认证。
- 正常释放及未到处理由后端执行，关闭页面后仍有效。
- 真实前后端、数据库、手机流程联调并保留实际结果后判定完成；页面模拟或单模块CI不代表整站通过。

## 四、同步、PR与记录

1. 获取最新main并合并进自己的功能分支，先保留未提交工作，正常解决冲突，不强制覆盖他人改动。
2. 根据本次同步说明检查故事受影响部分，PO同步需求和验收，开发人员拆分估算；不自动扩大Sprint承诺。
3. 接口/状态变更先更新共同契约，再实现前后端；提交关联真实PingCode编号，不编造新的工作项。
4. PR写明业务变化、代码/SQL/接口、真实检查结果和集成边界，由另一名开发人员检查后合并。
5. 实际AI辅助设计、代码、测试与评审如实记录，未执行的测试写未执行，不将AI自查记成人工验收。
